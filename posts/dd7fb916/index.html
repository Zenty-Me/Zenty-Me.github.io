async def 还是 def？

FastAPI 两种写法都支持，区别在于执行方式：

  • async def：在事件循环中直接执行。函数内部只能调用异步的 IO 操作（await 异步数据库驱动、httpx.AsyncClient 等），一旦调用了 time.sleep()、requests.get() 这类阻塞操作，整个服务都会被卡住。
  • def：FastAPI 会把它丢到线程池中执行，不会阻塞事件循环，适合调用同步库。

简单的判断原则：用到的库支持 await 就写 async def，否则写 def。

路径操作

方法装饰器

每个标准 HTTP 方法都有对应的装饰器：

  • @app.get()：获取数据，不改变服务器状态。
  • @app.post()：创建新数据。
  • @app.put()：完整更新已有资源。
  • @app.patch()：部分更新已有资源。
  • @app.delete()：删除资源。

另外还有 @app.options()、@app.head() 等。

请求与响应

路径参数

声明了类型 int 后，FastAPI 会自动做类型转换和校验：访问 /user/abc 会直接返回 422，并在响应中说明哪个参数校验失败。

注意路由匹配顺序：FastAPI 按照声明顺序匹配路由。如果同时有 /user/me 和 /user/{user_id}，必须把 /user/me 写在前面，否则 me 会被当作 user_id 去解析，结果返回 422。

使用 Path 校验

常用的数值校验参数：gt（大于）、ge（大于等于）、lt（小于）、le（小于等于）。

查询参数

路径函数中不属于路径参数的参数，会被自动当作查询参数，也就是 URL 中 ? 后面用 & 分隔的 key=value 键值对。

Python 3.10+ 中，Union[str, None]、Optional[str] 都可以简写成 str | None，后文会混用这几种写法。

使用 Query 校验

和 Path 类似，Query 可以给查询参数加上额外的校验与文档信息，推荐配合 Annotated 使用：

  • 字符串校验：min_length、max_length、pattern（正则）。
  • list[str] 类型的查询参数必须显式写 Query()，否则会被当成请求体。
  • 参数别名：Query(alias="item-query")，适用于 URL 中的参数名不是合法 Python 变量名的情况。

依赖注入

在 FastAPI 里，「依赖」是一个可调用对象（函数或类）。FastAPI 会在调用路径函数之前先执行它，再把返回值注入到参数中。公共参数复用、数据库会话管理、登录鉴权和权限校验一般都用依赖来做。

依赖嵌套与鉴权示例

依赖可以继续依赖其他依赖，FastAPI 会自动解析整条依赖链，同一个请求内相同的依赖只会执行一次，结果会被缓存。

依赖可以挂在三个层级上：

  • 单个路径函数的参数中，或装饰器的 dependencies=[...]；
  • APIRouter(dependencies=[...])，作用于该路由下所有接口；
  • FastAPI(dependencies=[...])，作用于全局所有接口。

真实项目中的 token 一般使用 JWT（如 pyjwt 库）签发和校验，FastAPI 也提供了 OAuth2PasswordBearer 等工具类，配合依赖注入即可实现完整的登录鉴权。

部署上线前建议检查：

  • 关闭 --reload，按需设置 --workers；
  • 数据库密码、密钥等敏感配置从环境变量读取，不要提交到仓库；
  • CORS 只放行实际使用的前端域名；
  • 不需要对外暴露接口文档时，可以用 FastAPI(docs_url=None, redoc_url=None) 关闭 /docs 和 /redoc；
  • 上线前执行 uv run aerich upgrade 同步数据库结构。
