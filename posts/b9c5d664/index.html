Hexo 博客发布笔记完整教程

发表于2026-08-06|更新于2026-08-06|博客搭建
|浏览量:

本篇记录从新建文章到部署上线的完整流程，方便以后查阅。

一、新建文章

执行后会在 source/_posts/ 下生成两个东西：

  • 文章标题.md：Markdown 文章文件
  • 文章标题/：同名文件夹，用于存放图片等资源

二、文章结构（Front-matter）

文章开头 --- 之间是 front-matter，用于配置文章元信息：

常用字段说明：

字段 作用 必填
title 文章标题 是
date 发布时间 是
tags 标签（列表） 否
categories 分类（列表） 否
cover 封面图路径 否
description 摘要（首页显示） 否

三、写作与图片处理

用 Typora 或任意 Markdown 编辑器打开 .md 文件写作即可。

图片存放规则

本站已开启 post_asset_folder，图片放在文章同名文件夹里。例如文章 我的笔记.md，图片就放在 我的笔记/ 文件夹下。

图片引用方式

文章里用裸文件名引用图片：

⚠️ 注意：必须用裸文件名（不带文件夹前缀），例如 ![](photo.png) 而不是 ![](我的笔记/photo.png)。否则部署后图片会 404。

Typora 配置建议

如果用 Typora 写作，推荐这样配置：

  1. 偏好设置 → 图片 → “插入图片时” 选 “复制到指定路径”
  2. 路径填：./${filename}/（Typora 变量，自动替换成文章名）
  3. 勾选 “对相对路径使用 ./“ 和 “应用上述规则到所有插入的图片”

这样图片会自动存到文章同名文件夹。但 Typora 生成的引用会带文件夹前缀，需要手动改成裸文件名，或安装 hexo-image-link 插件自动转换。

四、本地预览

访问 http://localhost:4000/ 预览效果。修改文章内容保存后刷新浏览器即可看到，无需重启服务。

预览草稿：

按 Ctrl+C 停止服务。

修改 _config.yml 或主题配置后必须重启 hexo server 才生效；只改文章内容不用重启。

写完满意后，一键部署：

部署后约 30 秒 ~ 2 分钟，GitHub Pages 自动构建完成即可访问。

八、常用命令速查

命令 作用
hexo new "标题" 新建文章
hexo new draft "标题" 新建草稿
hexo publish "标题" 草稿转正式
hexo server 本地预览
hexo server --draft 预览含草稿
hexo clean 清理缓存
hexo generate 生成静态文件
hexo deploy 部署到远程
hexo clean && hexo g && hexo d 一键发布
hexo list 列出所有文章
hexo version 查看版本

简写：g = generate，s = server，d = deploy，c = clean

九、常见问题

1. 修改配置后预览没变化？

改了 _config.yml 或主题配置文件需要重启 hexo server。只改文章内容不用重启。

2. 图片显示不出来？

按顺序检查：

  1. 确认图片放在文章同名文件夹里（不是 assets/ 或其他目录）
  2. 确认引用是裸文件名 ![](图片.png)，不带文件夹前缀
  3. 确认 _config.yml 里 post_asset_folder: true 已开启
  4. 确认 marked 配置了 postAsset: true

3. 部署后看不到更新？

GitHub Pages 有缓存，等 1-2 分钟或 Ctrl+F5 强刷。也可以去 GitHub 仓库的 Actions 页面查看部署状态。

4. 草稿为什么没部署上去？

_drafts/ 下的草稿默认不生成、不部署。用 hexo publish "标题" 转为正式文章后再部署。

以上就是 Hexo 博客发布笔记的完整流程。日常使用记住三步：hexo new 写、hexo s 看、hexo clean && hexo g && hexo d 发。
